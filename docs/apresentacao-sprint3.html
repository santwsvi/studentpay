Visao Geral

O que e o StudentPay

Professores distribuem moedas virtuais como reconhecimento de merito. Alunos acumulam e resgatam vantagens em empresas parceiras.

👨‍🏫

Professor

  • Recebe 1.000 moedas/semestre
  • Distribui com motivo obrigatorio
  • Consulta saldo e extrato
  • Saldo acumulavel entre semestres
🎓

Aluno

  • Autocadastro no sistema
  • Recebe moedas por merito
  • Resgata vantagens com cupom
  • Notificado por email
🏢

Empresa Parceira

  • Cadastra vantagens com custo
  • Define descricao e foto
  • Recebe email de conferencia
  • Gerencia ofertas ativas

Arquitetura

MVC em Camadas

Separacao clara de responsabilidades com comunicacao unidirecional entre camadas.

Controller
Endpoints REST (JAX-RS) — recebe requests HTTP, valida entrada, delega ao service. Nunca contem logica de negocio.
Service
Logica de negocio e orquestracao — autenticacao, envio de moedas, resgate, notificacoes por email.
Model
Entidades JPA com hierarquia — Usuario, Aluno, Professor, EmpresaParceira, CarteiraMoedas, TransacaoMoeda, Vantagem.
Repository
Acesso a dados via Hibernate Panache — queries tipadas, paginacao, sem SQL manual.
DTO
Objetos de transferencia — desacoplam representacao da API das entidades internas do dominio.
React (Vite)  ── HTTPS/JSON ──►  Controller  ──►  Service  ──►  Repository  ──►  PostgreSQL

Por que Quarkus?

Hot reload em dev mode (alteracoes refletem sem reiniciar), Panache elimina boilerplate de repositories, Dev Services sobe PostgreSQL automaticamente, startup em ~3s, SmallRye JWT integrado com CDI e padrao JAX-RS.

Persistencia

Estrategia de Mapeamento ORM

Duas estrategias de heranca JPA aplicadas conforme o contexto de cada hierarquia.

Usuarios

Estrategia JOINED

Tabela usuarios com atributos comuns (nome, email, login, senha, tipo). Tabelas separadas alunos, professores e empresas_parceiras com FK para o mesmo ID.

Sem colunas nulas Integridade por subtipo
Transacoes

Estrategia SINGLE_TABLE

Tabela unica transacoes_moeda com coluna discriminadora tipo (ENVIO, CREDITO_SEMESTRAL, RESGATE). Volume alto, queries frequentes no historico.

Queries rapidas Sem JOINs no extrato

Seguranca

Autenticacao JWT

Fluxo stateless com tokens assinados via chave RSA (RS256) e controle de acesso por roles.

1. POST /api/auth/login
Cliente envia login e senha em JSON.
2. Validacao BCrypt
Hash da senha comparado com BCrypt. Sem texto plano em nenhum momento.
3. Geracao do Token JWT
Claims: userId, nome, grupo (professor/aluno/empresa). Expira em 8h.
4. Endpoints Protegidos
@RolesAllowed("professor") restringe acesso. Token no header Authorization: Bearer.

Payload do Token

{
  "iss": "studentpay",
  "upn": "joao.aramuni",
  "groups": ["professor"],
  "userId": "c1b2c3d4-0001-...",
  "nome": "Joao Paulo Aramuni",
  "exp": 1778917542
}

Uso no Controller

@POST
@Path("/enviar-moedas")
@RolesAllowed("professor")
public Response enviarMoedas(@Valid EnvioMoedasRequest req) {
    UUID id = UUID.fromString(jwt.getClaim("userId"));
    professorService.enviarMoedas(id, req);
    return Response.ok(Map.of("message", "ok")).build();
}
